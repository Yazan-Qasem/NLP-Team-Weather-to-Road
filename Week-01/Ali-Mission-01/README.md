# ⚙️ مهام الطالب - الأسبوع الأول (1/11 - 14/11) [غير مكتمل]
### التخصص: تأسيس السيرفر وقاعدة البيانات الوهمية (Mock Database & API Layout)

- 
مهمة الطالب الخامس (مهندس السيرفر والربط الخلفي - Backend & API)

الهدف: تشغيل نموذج الذكاء الاصطناعي (RoBERTa) داخل سيرفر حي يستقبل أي نشرة جوية جديدة ويعيد الشوارع المتوقع إغلاقها.
• الأدوات المطلوبة: لغة Python مع مكتبة FastAPI و Uvicorn، وتطبيق Postman للاختبار.
• المدخلات (من مجلدك):
	1. ملف predictor.py (الذي يحتوي على دالة analyze_alert_and_predict_roads_smart).
	2. مجلد النموذج المدرب final_roberta_nyc_model (بعد فك الضغط عن ملف الـ ZIP المرفوع على Google Drive).
	3. ملف شوارع نيويورك NYC_Roads_Cleaned.csv (من شغل الطالب الأول).

خطوات التنفيذ المطلوبة منه:

1. تجهيز بيئة السيرفر: وضع الملفات الثلاثة (predictor.py، مجلد final_roberta_nyc_model، وملف NYC_Roads_Cleaned.csv) في مجلد واحد على جهازه، وتثبيت المكتبات المطلوبة (fastapi, uvicorn, transformers, torch, pandas).
2. بناء نقاط الاتصال (API Endpoints) في ملف main.py:
	• إنشاء نقطة اتصال POST /predict-closures تستقبل نص نشرة جوية جديدة بصيغة JSON (مثلاً: {"alert_text": "Winter Storm Warning in Queens..."}).
	• استدعاء دالتك بسطر واحد داخل السيرفر:
summary, roads_df = analyze_alert_and_predict_roads_smart(alert_text)
	• تحويل النتيجة (summary و roads_df) إلى صيغة JSON وإرجاعها كاستجابة (Response) للسيرفر.
	• إنشاء نقطة اتصال إضافية GET /live-weather-alerts (اختيارية لزيادة قوة المشروع) تسحب أحدث تحذيرات الطقس الحية لنيويورك مباشرة من رابط الـ API الرسمي (https://weather.gov) وتمررها تلقائياً لنموذجك.
3. الاختبار والتوثيق عبر Postman:
	• تشغيل السيرفر محلياً واختبار إرسال نشرات طقس خطيرة ونشرات ملغاة عبر برنامج Postman للتأكد من أن السيرفر يرد بسرعة وبدون أخطاء برمجية.
4. الربط النهائي مع الواجهة (Integration): تزويد الطالب الرابع برابط الـ API المحلي (مثل http://127.0.0) لكي تتصل واجهة Streamlit بالسيرفر مباشرة وتعرض النتائج الحية.
